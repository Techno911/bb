# Доработка bb (форк Артёма) · как выкатывать, чтобы ничего не падало

Эта папка `~/code/bb` это dev-репозиторий форка (ветка `feature/thread-project-dnd-and-panes`,
origin get-bb/bb, fork Techno911/bb). Живой bb Артёма работает НЕ из неё, а из неизменяемого
снимка `~/code/bb-runtime/current`. Правило одно: доработка попадает к человеку только через
конвейер с канарейкой. Всё остальное это тот самый «день сурка», когда после правки bb падает.

## Порядок доработки

1. Правь код здесь, тесты через turbo (см. корневой AGENTS.md). Коммить в текущую ветку форка
   обычным коммитом с понятным сообщением.
2. Выкат ОДНОЙ командой, она делает всё сама и уходит в фон:
   `~/code/bb-fork-switch/ship.sh` (по умолчанию HEAD, можно передать SHA).
   Она дождётся свободной памяти (арбитр), соберёт снимок, прогонит тесты и КАНАРЕЙКУ
   (второй сервер на копии `~/.bb`, живые сценарии Артёма обеими моделями), положит заявку,
   и сторож поставит снимок в тихом окне, потом прогонит те же сценарии на живом сервере;
   красный результат вернёт предыдущий снимок. Тебе ждать не нужно: результат в
   `~/.bb/logs/fork-stage-result.txt`, канарейка в `~/.bb/logs/canary-<sha>.json`.
3. В отчёте человеку скажи: коммит, что проверено тестами, и что снимок «встанет сам в тихом
   окне после канарейки». Не пиши «уже работает», пока сторож не применил.
4. Каждая доработка уходит наверх отдельным issue в get-bb/bb в тот же ход (сценарий человека,
   что сейчас, что ожидается, ссылка на коммит форка). Личное из текста убрать.

## Чего делать нельзя (каждый пункт стоил Артёму падения bb)

- Не запускать сервер из этой папки на данных человека: никаких `pnpm dev`, `bb-app.js start`
  с `~/.bb`, портов 38886/38887. Сторож видит такой сервер как «сборку мимо канарейки»
  и поднимает тревогу. Для проверки своей правки есть канарейка на копии данных:
  `python3 ~/code/bb-fork-switch/canary.py <sha>` после `release-manager.py --stage`.
- Не перезапускать окно bb, сервер, supervisor, host-daemon: ни `pkill`, ни `launchctl`
  по `com.chirkov.bb-fork*`, ни `open -a bb`, ни `osascript quit`. Это делает сторож
  через `maintenance-gate.py`, когда нет активных тредов.
- Не трогать `~/code/bb-runtime/*` руками и не удалять `~/.bb/daemon.lock`.
- Не менять `~/.bb/*` напрямую (база, конфиги, куки): данные человека.
- Не звать `stage-when-quiet.sh` вручную без агента: он делает одну попытку и выходит,
  повторяет его только LaunchAgent, который ставит `ship.sh`.
